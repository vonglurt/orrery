Read first

Three things in the repositories changed the design

None of these were assumptions. Each came out of reading what copal-prep.sh and copal-fleet.sh already do.

Already built

Terminal needs no change to a node

orrery’s README says a shell needs “a second credential with a wider door than the operator certificate has.” It has one. copal-prep.sh:28383 writes fleet-human into /etc/ssh/principals/$PI_USER, and copal fleet login has always signed -n fleet-operator,fleet-human.

One certificate, two principals, two doors: the forced command on one account, an ordinary login shell on the other. Stage 16 built it and the README recorded it as a gap.

Resolved

The session word settles GUI versus Control

The README records it unresolved: x11vnc cannot capture Wayland, --gui cannot run on X. They are not alternatives — /etc/copal/session selects the remote server and the console reads the word.

x11 nodes get Observe and Control over RFB, which src/rfb.rs already speaks. wayland nodes get them over RDP. On a Wayland node the console and Control now want the same session type.

The real limit

H.264 is where “no dependencies” breaks

Not SSH and not TLS — those are large, but every line has a published test vector. A video codec has no small correct subset, and libavcodec is a dependency on the one machine that cannot fetch one.

So EGFX is not negotiated. Plain bitmap updates with RLE instead — the same choice rfb.rs made asking for Raw and CopyRect only.

docs/console.md

The museum interface

Four regions, each a rectangle draw.rs already knows how to fill. There is no window manager inside the window: no floating panels, nothing overlapping. A pane that opens — a terminal, a screen, a result column — replaces the lab, so there is never a question of what is on top.

The arity of the selection is a first-class thing

Half the verbs mean something different on one node than on eight, and two of them mean nothing at all on eight. So the verb bar is redrawn every time the selection changes, and a verb that cannot apply is absent rather than greyed — the same rule the web console already follows for the write route in the gallery posture, for the same reason.

In the gallery posture the dispatch table is empty

On the web, the distinction is a route that does not exist. In a native window there is no route, so the equivalent commitment is that a keystroke which would have been a verb finds nothing to call. A gallery screen is a machine an unattended member of the public is standing in front of, and “the button is hidden” is not a security property.

Refused on purpose

Control on a multi-selection is a design decision, not a missing feature. Broadcasting keystrokes to eight machines produces divergent state nobody can see, and the operation actually wanted is Scene or Run — both declarative, both reporting per node. §IV-C of the lab report is emphatic and verbs.rs already encodes it. The button is simply not drawn when the selection is larger than one.

docs/wire.md

The credential rule, rewritten

The console’s architectural test was that it opens no socket, holds no credential, knows no subject names. A shell needs a key. SFTP needs a key. RDP needs a TLS session. So the rule is restated rather than quietly dropped.

The new invariant

orrery uses the operator credential it was pointed at. It never creates one, never stores one, never prompts for one, never forwards one, and never outlives one.

Six clauses, each of which is a check somewhere in the code. There is no keygen — a missing operator key is an absent button and a sentence, not an offer to make one. There is no password field anywhere in the program. The certificate’s eight hours are the session’s ceiling, counted down in the status line.

Four modules, and why they are one job

SSH and TLS want the same arithmetic. Write crypto.rs once and the second protocol is a wire format rather than a cryptosystem.

Host verification is the fleet’s, and it is better than ssh’s

ssh on the Mac checks a node against known_hosts — trust on first use, a file that accumulates, and a warning everybody learns to ignore when a node is reimaged. orrery has the fleet’s CA at ~/.copal/ca/<fleet>_ca.pub, and sign_one() installed a host certificate on every enrolled node. A reimaged node connects; a machine that is not this fleet’s fails at the signature. There is no first-use prompt, because there is nothing to decide.

The H.264 arithmetic, stated rather than hoped

A 1280×720 frame, 24-bit, uncompressed
2.6 MB
At 6 fps, full-screen changes
126 Mbit/s
A Zero 2’s link
100 Mbit/s
Interleaved RLE on a typical desktop
5–15×
What actually travels: damage rectangles
a few KB/frame

Which is to say: Control over RDP will be good for a desktop and bad for video. Dragging a window will be smooth; playing the exhibit’s video full screen will be a slideshow. The honest description of this feature is “you can drive a node from across the room”, not “you can watch it”.

NLA is refused. Network Level Authentication means CredSSP, which means NTLM, which means MD4, RC4 and a design whose entire purpose is to carry a password to a machine before that machine has proved anything. It is a large amount of code to implement a worse security property than the one already in hand.

Three defensible places to stop

After phase 3 there is a native fleet console on a Mac and on a node, with a selection model and per-node results, driving the CLI verbs that already exist — about 2,600 lines. After phase 6 it also has a shell and file transfer. Phases 7 and 8 are the part that can be cut, and they are the only part that depends on anything unverified.

Ranked, and named rather than glossed

What can go wrong

IDRiskIf it lands
R1 hypr-rdp will not send bitmap updates to a client with no H.264 decoder Control over RDP does not happen. wayvnc + rfb.rs instead — the code is written and tested. Phase 8 finds out before 2,200 lines, not after.
R2 hypr-rdp cannot be obtained or built at all Same fallback, found in the first hour of phase 8.
R3 Hand-written crypto has a subtle flaw Mitigated by test vectors and by narrowness — one algorithm per slot, verify-only where possible. Not eliminated. The argument is the LAN and the certificate posture, not “it is correct”.
R6 11,400 lines is a lot of program to hold The phase boundaries are the mitigation: 0–3 is a console, 4–6 is a console with a shell, 7–8 can be cut.
R4 objc_msgSend ABI mistakes in mac.rs ~25 distinct call signatures, no runtime class creation. Crashes loudly rather than silently.
R5 The baked US keymap is wrong for the operator Known and stated. A real limitation, not a bug — the alternative is libxkbcommon, a dependency, on the machine that cannot fetch one.
R7 The binary triples and a Zero 2 has 512 MB 1.4 MB resident against 22 MB for the Python prototype is still the argument. Measure on saskatchewan at phases 3, 6 and 9 rather than at the end.

The assumption under R1 and R2

hypr-rdp is not in either checkout, is not in Alpine’s package index as far as these repositories know, and nothing here has run one. Every claim in the design about what it will accept is written against the description it was given. Phase 8 therefore begins by obtaining it, running it on a node, and reading what it actually negotiates with a known-good client — not by writing a client against a guess.

And what would make the whole plan wrong

If a shell on a node turns out to be unwanted — if the real workflow is copal fleet run and never a prompt — phases 5 and 6 are 2,400 lines serving a button nobody presses. The way to test that is phase 3: use the console for a week with only the CLI verbs, and see what is missed.

If the Mac is not where the operator stands, phase 2 is 800 lines of AppKit for nothing. It is in the plan because answers.txt, the CA, the token ledger and the card reader are all there — but that is an inference from the repository, not something anyone said.

copal-alpine-linux/docs/fleet-control.md

The node’s half

Two new verbs in the forced command, and one refused

copal-fleet-exec is, in its own words, the security boundary, and a verb this file does not know is a refusal and a line in the log, not an attempt.

remote start | stop | status is the only genuinely new authority in the design — it lets a certificate holder put a machine’s screen on the network — so it is bounded four ways, all on the node: it reads /etc/copal/session and decides for itself which server to start; it binds to the LAN address only; it stops itself after COPAL_FLEET_REMOTE_MINUTES, default 30; and it logs both ends. This answers the README’s “Nothing on a node can start x11vnc.”

message TEXT is the banner the lab report wants and verbs.rs currently refuses to offer. 200 characters, a charset allow-list rather than a deny-list, and exec with the text as one argument — never a shell string.

send is refused and will not be added. Send is SFTP as the login user over the fleet-human door. A file-transfer verb in the forced command would mean the service account growing the ability to write arbitrary paths, which is the boundary the file exists to hold. Two doors, two jobs — collapsing them would make the forced command decorative.

What does not change

  • fleet_sshd_policy() — the Match block, the forced command, PermitTTY no, AllowTcpForwarding no. All of it stays exactly as written.
  • The principal files and cmd_login() — already correct, and the reason Terminal costs nothing on the node.
  • The CA’s handling — orrery reads the public half to verify host certificates and never touches the private half. A program holding both would be a program worth stealing.
  • The bus — nothing here publishes, subscribes, or knows a subject name.
  • The card-writing path — copal-prep.sh picks the disk and asks for both typed ERASE confirmations. The pane is a front end to that, not a replacement for it.

The acceptance test is the morning, not a build

§V of the lab report, driven from the window instead of the terminal: eight tiles at 08:31, one missing. Click the north tag, Power on. Notify all-up chimes at 08:34. Terminal into museum-03, no password asked. Send an exhibit asset to the wall tag — two nodes, two results. Control museum-06, which is Wayland. Scene show on all eight: seven results and one refusal, drawn as seven and one rather than as a failure. Write card 8, the only unused token in the ledger, and watch the manifest gain a row. At 17:00, Power off, and the certificate expires by itself an hour later.

One of those nine steps can fail for a reason nothing here controls. Every other step is built out of things that exist.
