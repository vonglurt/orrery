Orrery · the build, end to end

A console for a room of machines, written without a single dependency

Eleven phases turned a read-only web wall into the thing an operator stands in front of: a room of eight machines you select from, a row of verbs that act on the selection, and five protocols underneath them that were all written by hand — because the one machine this has to run on cannot reach the internet to fetch a crate.

What it is now

Three faces on one read model

Every screen renders copal fleet state and nothing else. A node that is not in that document cannot be dialled, and there is no second way of learning anything — a console that discovered nodes for itself would be a second fleet.

The schedule, as it actually went

The rule that shaped every phase

No fake where a real server exists. A hand-written server agrees with the client’s own reading of the specification, including wherever that reading is wrong. Four of the five protocol phases ended up proved against somebody else’s implementation, and each of those found something a fake never would have.

The wire

Five protocols, one whitelist

profile.rs names one key exchange, one host-key algorithm, one signature algorithm and one cipher to offer. A test fails the build if sha1, cbc, rc4, ssh-rsa or ecdsa ever appears on a list — and orrery --profile-sshd prints the same list as sshd_config lines, which the node writes into its own configuration and whose drift make lint refuses.

the gate

A certificate, never known_hosts

The host key must be an ssh-ed25519-cert-v01 from the fleet CA, of the host kind, naming that node, valid now — and then the node has to prove it holds the certified key. No trust-on-first-use, no prompt, no bare-key branch. The signature is checked before the principals and the dates, because until then they are text an attacker chose.

the lockdown

Mutual TLS is what stops a standard client

The node demands a client certificate from the fleet CA. mstsc and FreeRDP have none and cannot be given one, so their handshake ends before RDP begins. Proved against s_server -Verify 1: in with the certificate, out without it.

the narrowing

One suite offered, two accepted

In SSH the client’s preference decides, so offering ChaCha first and offering it alone are the same session. In TLS the server picks — so the ClientHello names exactly one suite, because the alternative runs at half a megabyte a second.

What running it found

Six things no amount of reading would have caught

1 · GSSAPIAuthentication no is an error on Alpine

OpenSSH there is built without GSSAPI, so the line the profile rendered made every connection log a complaint about the node’s own configuration. Found on the first run of ssh-check.sh against a real sshd; the line is gone and a test keeps it gone.

2 · The bitsliced AES costs 370×, not “a few”

Measured rather than assumed: 186.1 MB/s for ChaCha20-Poly1305 against 0.5 MB/s for AES-256-GCM. Since a TLS server picks the cipher and rustls prefers AES, offering both would have handed a Raspberry Pi the slow one. That is why tls.rs offers one suite — and why a test now runs an AES-only server and requires the console to refuse it.

3 · The transcript bug that only appears with a client certificate

TLS 1.3’s application keys come from the transcript up to the server’s Finished and nothing after it. Working that point out by arithmetic at the end of the handshake was right while the client sent only a Finished, and silently wrong the moment it also sent a certificate: a handshake that completes and then cannot decrypt a byte.

4 · FreeRDP will not serve an Ed25519 certificate

It derives its channel bindings by hashing the certificate with the digest named in the signature algorithm, and Ed25519 names none. unable to retrieve bindings, and the connection drops before RDP starts. That is a finding about the fleet’s one-algorithm-everywhere decision rather than about this code — and it is why the RDP suite runs against xrdp instead.

5 · fcntl is variadic, and declaring it otherwise is silent

C declares it int fcntl(int, int, ...). Declared with a fixed third argument it compiles, links and runs — and on aarch64 Darwin the variadic convention passes that argument on the stack while a fixed one goes in a register, so O_NONBLOCK never arrived. Every read meant to return immediately blocked until the far end spoke. It hid for two phases because every read happened after a question had been asked, and appeared the instant something read a pipe before asking one. Two tests now ask for nothing and require an answer anyway.

6 · Three drawing bugs that a green test run cannot see

Rect::cut_bottom returns the piece it took first, the opposite of cut_top — the whole file browser drew inside a forty-pixel strip. The gutter between its columns was never painted, so it showed the canvas’s own zeroes as a black hole. And a button labelled ← copy drew as copy, because the font baked U+2192 and not U+2190 and a missing glyph is a blank cell rather than a panic. All three were found by rendering a frame to a file and looking at it.

What was refused

The absences are the design

  • Observe. It wanted a thumbnail from every node. Nothing produces one and nothing will: a node capturing its screen every few seconds is a capture daemon on every machine in the museum, running whether or not anybody is looking, and — unlike the screen verb — it cannot be bounded by a deadline. Refused, with the shape that would fit written down instead.
  • NLA. CredSSP means SPNEGO means NTLM: MD4, RC4, and a design whose whole purpose is to carry a credential to a machine before that machine has proved anything.
  • H.264. A video codec has no small correct subset and libavcodec is not on an Alpine node, so RDP negotiates plain bitmaps with RLE — the same trade the VNC client made in asking for Raw.
  • Drawing orders. The RDP capability set advertises support for not one of them, which obliges the server to send bitmaps. A drawing-order interpreter is a second rendering engine to keep correct.
  • Wildcard certificates, passphrases on keys, minting credentials, caching the read model, Control on a selection. Each has a sentence in the code saying why.

Still open

What this does not prove

The truth pass exists to keep this list accurate rather than to shorten it.

  • Nothing has run on a Raspberry Pi. The whole program cross-compiles to aarch64-unknown-linux-musl and its Linux suite passes in a container on a Mac, which is not the same claim.
  • No node has run hypr-rdp. The RDP client is proved against xrdp — a different implementation by other people, and not the one a Wayland node will run.
  • The operator has no X.509 certificate yet. Mutual TLS works; the fleet CA is an SSH CA, and issuing X.509 from it needs an ASN.1 writer beside the signing path. Until then Control refuses with a sentence naming the file it wanted.
  • Hand-written cryptography is not reviewed cryptography. Narrowness reduces the surface; it does not make this rustls. The risk is kept where it can be read.

And the next five days of work, priced

One SSH connection per node instead of one per verb (a second saved per session, eight per fan-out); row-wise blitting instead of per-pixel (the reason Control feels heavy); one byte writer instead of three (150 lines, and three places to get a length wrong becomes one); one pane lifecycle; one fixture script for the container suites. Each is written up with what it costs today and what the fix costs, because a refactoring list with no prices on it is a wish list.
